# Scope

## Confirm scope before editing

Before changing anything, confirm which files and layers are in scope, and whether existing code is kept or replaced. If the task doesn't say, ask.

## Make the minimal change

Make the smallest change that fully does the task. Don't over-engineer, and simplify immediately when pushed back on complexity.

## No extra scope

Don't add drive-by refactors, renames, reformatting of untouched lines (e.g. running Pint on a directory), new features, or "while I'm here" fixes. Report anything else you notice instead of changing it.
